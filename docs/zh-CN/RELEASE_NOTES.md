# 0.1.0-alpha.21（本地、尚未发布、无损数值文本）

- 两个引擎的默认有限数值文本使用同一个最短往返还原格式化器：覆盖 print、即时占位符、to_text、文本／CSV／TSV 单元格和数组。保留带符号零。显式显示精度保持不变。
- JSON／封存序列化及原生程序精确位模式清单保持完整。继续拒绝非有限值和不安全的整数输入。
- 经哈希的语义政策推进至 round-trip-numbers.v2。历史证据仍可验证；执行 alpha.20 及更早版本的冻结程序须显式修订。输出哈希可能改变。
- VS Code 0.1.16 和 JetBrains 0.3.6 包含相应的补全帮助。

参见 `docs/NUMERIC_TEXT.md` 和 `examples/numeric_text.gbl`。没有新增依赖。跨平台数学、复合单位字面量及 GBL-005 起的工作仍在队列中。这不是任意精度或精确整数功能。

## 上一阶段：0.1.0-alpha.20（受保护值）

- 所有注册常量别名均为只读，包括 `h`（普朗克常量）。在右侧表达式求值之前拒绝赋值；检查嵌套绑定。表达式、模板和 `seal h` 解析到同一个注册表值，并记录其使用。
- 拒绝丢弃仅返回值的注册内置函数调用结果。`append` 仍采用副本语义：使用 `a = append(a, value)`。有副作用的输出／输入调用和用户函数调用仍可作为合法语句。
- 源代码字符串字面量在求值时捕获 `{name}`／`{name:.Nf}` 占位符，包括赋值、函数返回和数组元素。输出和输入提示绝不重新解释已存储文本。用户输入、参数和导入数据保持普通文本。`{{name}}` 写出 `{name}`。
- 解释程序和原生程序共享有界模板扫描器。新运行／冻结记录经哈希的 `language_semantics` 政策。历史运行和旧冻结记录的完整性仍可验证，但旧冻结源代码必须显式修订，才能采用改变后的执行语义。即使输出一致，diff 报告仍标记 `LANGUAGE_SEMANTICS_CHANGE`。
- VS Code 0.1.15 和 JetBrains 0.3.5 的补全帮助记录常量保护、append 结果使用和即时捕获规则。

没有新增依赖。数值往返还原格式化、确定性数学、批量 FITS 选择／导出、带种子 RNG 和更大的预算仍在队列中。参见 `docs/PROTECTED_VALUES.md` 和 `examples/protected_values.gbl`。

## 上一阶段：0.1.0-alpha.19（表格／模块／原生 I/O）

新增十个显式 CSV／TSV 读取函数：行／列计数、表头、文本列和经检查的数值列。强制执行 UTF-8、引号规则、严格行形状、唯一表头和资源限制，拒绝缺失／非有限数值。输入字节及请求访问内容均被保存，并可独立验证。

新增顶层 `import "relative/library.gbl"`，以便复用 `g_func` 库。库仅包含定义／导入；没有隐藏的顶层执行。循环依赖、符号链接、路径穿越和重名都会失败。冻结程序固定原始库依赖图；规范化哈希和运行验证包含该图。

编译器现在通过共享 Rust 辅助代码支持现有 FITS 读取、文件写出和绘图，以及新的表格读取。原生运行时不使用 Goblin++／Python 进程，也不解析源代码。审计运行比较原生与参考执行的输入／输出证据及字节；生成的支持源代码保存在经哈希的清单中。数据编译使用锁定的离线 Cargo，要求依赖已缓存。独立可执行文件具有明确且独立的输出／保管链边界。

VS Code 0.1.14 和 JetBrains 0.3.4 新增对应高亮和补全。参见 `docs/DATA_MODULES_NATIVE.md` 和 `examples/csv_modules.gbl`。没有新增依赖。本阶段不宣称提供批量导出、FITS 写入、自动单位或缺失值推断、外部包导入或更多统计函数。

## 上一阶段：0.1.0-alpha.18（统计功能第一步）

两个执行引擎新增 `sum(array)` 和 `mean(array)`。它们要求非空、同质数值数组，保留 SI 量纲，并使用同一个共享补偿求和实现。mean 使用幅度缩放，避免本可避免的求和溢出。空数组、非数值、不兼容量纲及溢出输入都会显式失败；不悄悄跳过任何值。已有名为 `sum` 或 `mean` 的变量仍合法，但这些名称现在保留给内置函数调用，不能用作用户函数名或函数参数名。

当前编辑器源码为两个函数加入补全和帮助。这仅是统计功能第一步：此变更没有实现中位数、方差、标准差、权重、CSV 读取和不确定度传播。参见 `docs/STATISTICS.md` 和 `examples/statistics_basics.gbl`。

## 上一阶段：0.1.0-alpha.17

在两个执行引擎中，新增电流作为第六个 SI 基本量纲、34 种电学单位拼写和 18 个 `ee_` 函数。辅助函数涵盖欧姆定律、带符号功率和能量、电荷、串联／并联电阻、RC 时间常数、理想电容／电感能量、显式 KCL／KVL 残差和容差检查，以及电学单位报告。

新运行及冻结证据包含版本化电学注册表和六轴量纲。历史仅常量冻结记录及 alpha.16 科学冻结记录保留其原始五轴检查；接受旧五轴原生清单，电流指数置零。一般逆时间显示仍为 `1/s`，以保持已有角速度输出。

VS Code 0.1.12 和 JetBrains 0.3.2 包含对应补全、高亮、单位和函数帮助。参见 `docs/ELECTRICAL_ENGINEERING.md` 及可运行的 `examples/electrical.gbl`。

## 上一阶段：0.1.0-alpha.16

两个执行引擎新增范围刻意受限的化学基础：版本化的 43 种常见元素注册表、精确符号原子查询、有界化学式摩尔质量，以及经过量纲检查的物质的量、质量、物质的量浓度和稀释辅助函数。新增实用体积、波长、压强和原子质量单位，以及 `R` 和 `m_u`。

化学注册表标识和 SHA-256 现在出现在运行证据中；冻结回执使用的综合科学注册表包含常量、单位和化学参考数据。不支持的化学式语法和量纲错误显式失败。本阶段刻意不包含同位素、电荷、水合物、反应、配平、pH、平衡、动力学、热力学状态、不确定度和生物序列语义。

直到 alpha.15 的历史冻结回执仍保留原始仅常量注册表检查，并继续可验证。新 alpha.16 冻结记录绑定扩展后的科学注册表；验证会标记历史路径，而不声称旧回执涵盖当时尚不存在的数据。

VS Code 0.1.11 和 JetBrains 0.3.1 编辑器源码新增对应化学补全、文档、高亮、常量和单位；运行时语义仍是权威依据。

## 上一阶段：0.1.0-alpha.15

新增经量纲检查的天文距离转换、同质向量 `magnitude`／`dot`／`cross`、显式笛卡尔／极坐标／球坐标转换、线速度、名称明确的伽利略和共线狭义相对论速度叠加、角速度、切向速度、向心加速度及角动量。所有函数均可在 Rust 解释器和原生编译器中运行。

坐标与角度约定属于公开接口：`d` 表示度，`r` 表示弧度；球坐标倾角从 +z 测量，方位角从 +x 朝 +y 测量。拒绝具有无效量纲、原点歧义、无效半径或倾角、非正经过时间、或超光速相对论操作数的输入。本阶段刻意不宣称提供广义相对论、参考系、张量、轨道传播或不确定度语义。

## 上一阶段：0.1.0-alpha.14

Rust 解释器和原生编译器新增明确角度约定的三角函数。`sind`／`cosd`／`tand` 接受以度为单位的数值；`sinr`／`cosr`／`tanr` 接受弧度数值；反函数和双参数形式使用相应的 `d` 或 `r` 后缀表示结果单位。`deg2rad` 和 `rad2deg` 提供显式数值转换。本阶段输入仍为无量纲量；不会悄悄将 `deg` 和 `rad` 引入为物理单位。

为保持兼容，alpha.13 无后缀名称仍保留弧度行为，并在每次运行中，对每个函数名发出一条保留的 `G302` 迁移警告。它们不会悄悄改变含义。alpha.14 验收门槛涵盖两个执行引擎、警告证据、定义域和量纲拒绝、原生结果一致性、文档、示例、能力输出以及 VS Code 编写支持。

## 上一阶段：0.1.0-alpha.13

Rust 解释器和原生编译器新增具有量纲感知的科学数学功能：`abs`、`sqrt`、可变参数 `min`／`max`、`floor`、`ceil`、`round`、`exp`、`ln`、`log10`、`sin`、`cos`、`tan`、`asin`、`acos`、`atan`、`atan2` 和 `hypot`。平方根只接受单位指数均为偶数的非负量。对量纲敏感的函数要求兼容单位；超越函数和舍入函数要求无量纲值。定义域、量纲、参数数量、溢出及解释器／编译器一致性路径均有被保留且可独立验证的测试覆盖。

VS Code 编辑器源码现在为这些内置函数提供高亮、补全和文档。本阶段刻意不新增隐式角度单位、分数量纲、复数或悄悄传播的 NaN／无穷值。

## 上一阶段：0.1.0-alpha.12

日常语言易用性阶段。新增短路布尔 `and`、`or` 和 `not`；最近循环的 `break` 和 `continue`；直接遍历独立的一维数组值；带检查的整数 `%`；以及 `parse_integer(text)`。所有新增功能均可在 Rust 解释器和原生编译器中运行，保留共享循环预算，生成新的规范化 AST 形式而不改变旧程序哈希，并有正向与负向验收测试。VS Code 扩展源码已更新以支持新语法。

整数功能刻意限于 `f64` 可精确表示的整数（±(2^53−1)）；这不是任意精度整数类型。直接遍历不会流式读取 FITS 行。编译后的 FITS／输出一致性和模块系统仍是后续可独立审查的里程碑。

### 打包与第三方声明

macOS arm64 二进制归档包含 `THIRD_PARTY_NOTICES.md` 和 `third-party/` 声明包，由精确锁定的常规依赖树和当前 Rust 标准库文档生成。该包保留此目标依赖树全部 40 个外部包的上游许可证文件，包括 `unicode-ident` 使用的附加 Unicode 条款，以及 Rust 库版权和许可证文件。收集器可通过 `tools/collect_third_party_notices.py` 离线复现。这些证据针对特定目标；锁定文件、Rust 工具链、目标、功能或打包改变时，必须重新生成。

## 上一阶段：0.1.0-alpha.11

新增 `fits_select_stats`，用于有界、全表的标量数值 FITS 选择及可选正权重。半开区间和列名均为显式指定；返回选中行数、可用行数、权重和及平均值。适用 FITS 空值／缩放规则；非正权重和非有限累积结果失败；运行回执记录选择参数。随附的三行样例是功能测试，不是科学 DESI 结果。FITS 调用仍仅支持解释器。日常文本操作和带提示的 `input()` 已实现，现已在公开发布检查清单中特别说明。

## 上一阶段：0.1.0-alpha.8

两个 Rust 执行引擎新增一维同质数组、从零开始的索引和索引赋值、半开切片、`len` 和 `append`。数组赋值、切片和 append 使用独立值副本。数组封存、原生一致性清单、规范化哈希、冻结拒绝和负向路径均有测试。包含 0.1.0-alpha.7 交互工作：`input`、只读 `argc`、`argv`、`--` 程序参数、保留交互证据和编辑器提示桥接。数组上限为 100,000 个元素；尚不支持嵌套数组和输入文本的数值转换。

## 上一阶段：0.1.0-alpha.6

Rust 解释器和原生编译器新增 Goblin++ `if`／`else if`／`else` 及 `switch`／`case`／`default`。`if` 条件必须为布尔值。`switch` 对选择表达式求值一次，按顺序惰性测试标签，使用精确且具有量纲感知的相等比较，执行第一个匹配分支且不贯穿，并可选择执行最后的 `default`。分支可与循环组合，共享已有运行、冻结、验证和可选封存政策。已有规范化哈希保持不变。

分支验收测试涵盖解释器／编译器一致性、无贯穿、惰性条件与标签、嵌套循环、类型／量纲失败、格式错误语法、可验证失败及冻结源代码拒绝。即使位于不可达分支中，FITS 和生成输出调用仍不能原生编译；请解释执行此类程序。集合、用户自定义函数、布尔组合器和经认证的账本作者身份仍是后续工作。

## 上一阶段：0.1.0-alpha.5

日常编程阶段：`GO_PARANOID` 和 `seal` 为可选。`print`、安全生成输出函数、FITS 访问和循环均可不使用这两个指令。文件输出仍限制在唯一运行目录中，受上限约束、经哈希且可验证。显式请求时，`seal` 继续对具名值创建快照。

`GO_PARANOID` 现在具有具体的附加证据政策：执行后再次观察源代码并保存字节；拒绝不匹配／缺失证据；在登记保管链账本前，独立验证回执／证据。自检失败成为 `G405`，不能登记未经验证的回执。运行回执模式 v2 记录此证据，而验证器继续接受 v1。执行后检查检测该时刻存在差异的字节；它不是持续监控，也不是操作系统沙箱。已有冻结、内联 Rust 授权、FITS 和输出防护在两种模式均适用。

已有 alpha.4 循环实现保持不变。其局限包括缺少条件语句、集合、用户自定义函数、编译后的 FITS／输出调用和经认证的账本作者身份。

## 上一阶段：0.1.0-alpha.4

日常控制流阶段。`for ... in range(...) { ... }` 和 `while condition { ... }` 现在可作为 Goblin++ 语法在 Rust 解释器和原生编译器中执行。

新增布尔字面量、比较运算符、嵌套块、有符号半开范围，以及每次运行全局一百万次循环体迭代上限。超出预算的循环及无效范围／条件类型显式失败，并作为可验证运行保留。布尔封存与编译结果进行检查。编译后的 seal 现在在 `seal` 语句处捕获值，与解释器一致，即使在循环内部也是如此。

旧 0.0.7 语法语料仍处于回归测试中；四个以前被拒绝的比较案例被明确重新归类为有意的 alpha.4 扩展。旧规范化哈希（包括能量示例）保持不变。

这是实用控制流基础，并不宣称 Goblin++ 已是完整日常语言。条件语句、集合、用户自定义函数和批量／加权 FITS 行操作仍是后续工作。循环限制不是已授权内联 Rust 的沙箱。
