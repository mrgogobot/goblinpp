# 安全与信任边界

## 运行证据的保密性

Goblin++ 保存源码和运行日志。根据程序的行为，其运行目录和证据存储还可能包含未经脱敏的 `input()` 提示和响应、程序参数、导入库及 FITS/CSV/TSV 字节、封存值，以及生成文件。这些记录不加密。除非你已审查存储位置和操作系统访问控制，否则请避免使用密码、访问令牌、个人信息或保密研究数据。从实时源码中删除秘密，不会抹除已保存在运行证据或备份中的副本。

`GO_PARANOID`、哈希、冻结回执和保管链账本可检测部分变化；它们都不提供保密性。确切的交互证据行为见 [输入、参数、数组与切片](INTERACTION_AND_ARRAYS.md)。

## 日常模式与严格审计模式的证据

日常运行仍保存起始源码、stdout、stderr、已计算哈希的回执、生成的及显式封存的产物、相关导入，以及通常的一条校验和账本事件。如果严格审计模式运行未通过自身回执／证据检查，它会记录执行机制失败，不会将未经验证的运行注册到账本。省略 `GO_PARANOID` 不会禁用输出路径约束、冻结源码检查或内联 Rust 的精确哈希授权。

`GO_PARANOID` 还会在运行后重新读取普通源码文件，保存观察到的字节，将其 SHA-256 与起始源码比较，并在不匹配或无法获取时拒绝 `PASS`。无法保存运行后证据也会被记录为拒绝。运行时在尝试注册账本前，独立验证已完成的回执和证据。回执模式 v2 记录该运行后状态；`verify` 继续接受现有 v1 回执。这种观察不是原子文件系统快照或持续监控：在运行后检查之前已恢复的临时更改可能逃过检查，之后对实时源码的修改也不属于已保存运行。已保存的起始源码仍是执行依据。

两种模式都不是操作系统沙箱，也不构成经过认证的作者身份声明。特别是，获授权的内联 Rust 以用户完整的文件系统和网络权限运行。

## 内联 Rust

内联 Rust 具有运行该编译程序的用户权限。它可以读取、修改、传输或删除该操作系统账号能够访问的任何内容。Goblin++ 不会假装内容哈希就是沙箱。

强制执行的控制包括：

- 解释器模式拒绝所有内联块；
- 编译执行模式要求每个块的精确 SHA-256；
- 授权记录在运行回执中；
- 生成的 Rust 被保存以供审查；
- 原生二进制文件和生成源码分别计算哈希；
- 源码编辑会使代码块授权及任何源码冻结失效；
- 内联块不能通过受支持的 alpha 接口修改 Goblin++ 变量。

仅在真正的操作系统级沙箱或一次性机器中运行不受信任的内联 Rust。`GO_PARANOID` 加强证据与拒绝行为，但不能使任意原生代码变得无害。

## FITS 与科学输入

FITS 文件是不受信任的二进制输入。读取器检查 HDU／头块边界、必需的结构关键字卡、支持的 `BITPIX` 和 `TFORM`、轴及行大小、算术溢出、截断、空值和数值缩放。输入符号链接会被拒绝。读取基于持续打开文件的位置访问，内存使用有独立于文件大小的上限。

普通运行对完整输入计算哈希，然后对证据副本计算哈希；因此，运行期间并发的就地更改会使运行成为执行机制失败。在支持硬链接的情况下，按校验和寻址的证据存储通过硬链接避免重复的物理副本。已存储对象受损时会拒绝，而不是悄悄替换。`fits-info --quick` 跳过哈希，并明确标记为 `QUICK_INSPECTION_UNHASHED_NOT_EVIDENCE`。

应将 alpha 限制当作限制，而不是推断不受支持的天文学语义的许可。Goblin++ 尚不解释 WCS、FITS 元数据所命名的单位、不确定度模型、ASCII 表值、压缩图像、位／复数列或变长数组。`Z` 这样的 FITS 列名是数据，不是受到认可的宇宙学解释。

## 生成输出

Alpha.19 通过锁定依赖、离线构建的 Cargo 支持库，将编译执行扩展到科学 I/O。共享支持源码和原生输出清单会计算哈希。原生／参考一致性检查不是沙箱，也不是科学正确性的证明。独立可执行文件缺少启动器的保管链／冻结／运行后检查；需要这些检查时，请使用经审计的 `--compile` 运行。

源码程序不能通过受支持的输出 API 写入任意文件系统路径。输出名称必须是一个普通文件名：绝对路径、目录、`..` 和重复声明会被拒绝。运行时仅在唯一运行目录下创建文件，采用仅创建新文件语义，且每个文件上限为 64 MiB。验证在读取回执路径之前，将它们约束回该输出目录。

绘图元数据绑定导入 FITS 的摘要和确定性采样描述。图仍是可视化，不是已声明科学选择规则的替代品。省略 JPEG，是因为有损像素不适合作为唯一的权威科学产物。

内联 Rust 仍在该边界之外。获授权的原生块具有用户完整的操作系统权限，可以在账号允许的任何位置写入。

## 本地模块与分隔文本输入

导入接受入口目录下相对、无路径遍历的 `.gbl` 路径，拒绝符号链接路径分量、循环依赖和重复函数名，并只允许库中包含函数定义和导入。它们绝不获取包。冻结固定原始模块字节；严格审计模式的运行后检查观察导入哈希。与根源码观察一样，这不是持续监控或原子文件系统事务。

CSV/TSV 读取采用有大小限制的 UTF-8 快照，使用显式分隔符、表头和数值转换。缺失或格式错误的数值单元格会失败；绝不会悄悄跳过数值或赋予推断出的单位。这些限制并不认证输入数据的来源或科学有效性。

## 循环限制

解释器和编译执行的循环共享每次运行 1,000,000 次循环体迭代的上限，包括嵌套循环。超出上限会成为已保存的执行机制失败。这防止普通的意外无限循环；它不限制单个科学函数调用所耗时间、生成输出各自上限之外的内存使用，或已授权的内联 Rust。`GO_PARANOID` 和内联 Rust 块必须位于顶层，因此循环控制不能悄悄改变其授权模型。

## 保管链

alpha 账本通过 SHA-256 哈希链使篡改可被察觉，但不认证作者身份。其 CLI 报告 `CHECKSUM_ONLY`。Ed25519 签名和崩溃恢复仍是待完成的移植关卡。请独立备份源码和证据目录。

## 依赖

发布依赖由 `Cargo.lock` 固定，Cargo 验证注册表包的校验和。发布清单对每个随附文件计算哈希，但清单自身除外。
