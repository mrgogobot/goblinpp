## 第 1 层：静默或误导性结果

### 用户提供的验收示例（2026-10-02）

保留这些完全一致的示例，作为预期行为契约：

```goblin
h = 2                 # must refuse: h is a registered constant
a = []
append(a, 1)          # must refuse (or mutate a)
x = 1
s = "{x}"             # must interpolate now, or refuse
x = 2
write_text("t.txt", s)   # must never silently write 2
```

这些是**修复要求**，不是宣称 alpha.19 目前通过这些要求。应实现为三个独立回归程序，而不是一个组合测试：首次有意拒绝不能掩盖其他案例。

1. **常量绑定（GBL-001）：**`h = 2` 必须失败，诊断中说明 `h` 是注册常量，并在其能作为变量使用之前拒绝。
2. **空数组 append（GBL-002）：**`a = []; append(a, 1)` 不能悄悄通过且让 `a` 仍为空。在优先采用的副本政策下，应拒绝被丢弃的结果，并解释 `a = append(a, 1)`。若刻意采用可变设计，则须证明 `a == [1]`；记录此示例并不代表已选择或实现该替代方案。还应测试在副本政策下，空数组 append 的赋值成功。
3. **存储模板（GBL-003）：**独立运行从 `x = 1` 到 `write_text` 的四条语句。快照插值必须导出捕获的值 `1`（包含写出函数文档规定的换行），或赋值必须显式拒绝未解析的存储模板。禁止成功导出 `2`。在拒绝政策下，不应生成 `t.txt`。

Alpha.20 选择独立副本 append 加丢弃调用拒绝，以及即时模板捕获（不是替代的拒绝政策）。

根据所选诊断阶段，让每项契约经过检查、解释执行和编译执行。分别验证保留的失败证据和科学成功。测试直接及存储字符串、循环和转义字面花括号，不引入意外延迟插值，也不禁止普通文本。

### GBL-001 — 注册常量不得与变量赋值冲突

**Alpha.20：**所有常量别名受保护，表达式／模板／封存解析一致。以下复现记录旧 alpha.19 行为。

最小复现：

```goblin
h = 9
print("{h}")  # Prints 9 from the environment.
print(h)      # Prints Planck's constant from the constant registry.
seal h        # Reads the assigned environment value.
```

赋值被保存，并非简单忽略。表达式名称解析优先使用解析器分配的常量 ID，而插值和封存读取环境。这种不一致本身就是完整性风险。涉及 `src/parser.rs`、`src/evaluator.rs` 和 `src/compiler.rs`。

- 拒绝向每个注册常量拼写／别名进行普通赋值，并给出直接诊断，例如 `h is a registered constant; choose another
  variable name`。不要悄悄允许遮蔽。
- 审计所有绑定途径，包括索引赋值、函数名、参数和循环变量。一些途径已经拒绝保留名称；应实施一致规则，而非假设所有途径都存在问题。
- 验收：从注册表枚举别名；覆盖已注册的 `h`、`G`、`c`、`R`、`k_B`、`N_A` 和 `pi`；验证解释器／编译器及 `check` 一致、失败被保留，且表达式／插值／封存不会对成功赋值的值产生分歧。

### GBL-002 — 被丢弃的 `append` 不得悄悄成功

**Alpha.20：**拒绝被丢弃的直接仅返回值内置函数调用；保留副本语义。对用户定义／有副作用的语句并未实施通用未使用结果检查。

```goblin
a = [1, 2]
append(a, 3)
print("{a}")  # Currently [1, 2], with RUN_STATUS=PASS.
```

`append` 返回独立数组；表达式语句对该结果求值后丢弃。这与已有副本数组设计一致，但语句静默无操作会误导用户。

- 首选方向：保留值／副本语义，拒绝被丢弃的纯函数结果，并提示 `Use a = append(a, x)`。未经明确语言设计决策，不要将 `append` 改为原地修改。
- 区分纯／产生值的调用和合法有副作用的语句，如 `print`、文件写出及有意产生副作用的用户函数。全面禁止所有丢弃调用会破坏有用代码。
- 验收：赋值 append 仍有效、副本仍独立、丢弃 append 明确失败；覆盖嵌套／块／函数上下文；允许的有副作用语句在两个执行引擎均能运行。

### GBL-003 — 存储文本不得从后续环境获取值

**Alpha.20：**Malin 选择即时捕获。源字符串表达式只解析一次；输出绝不再次展开文本。参见[迁移](PROTECTED_VALUES.md)。以下记录历史错误，不是当前预期行为。

```goblin
x = 1
line = "saved x = {x}"
x = 2
print(line)                         # Currently saved x = 2.
write_text("late_template.txt", line) # Currently writes saved x = 2.
```

字符串按字面保存。输出函数随后按当前环境插值其文本（`export_cell` 对文本导出也如此）。因此，循环中累积这些字符串可能在导出时捕获错误值。`src/evaluator.rs` 和 `src/compiler.rs` 中生成的插值代码需要共同审查。

- 决定并记录何时进行插值。可选方案包括字符串创建时对插值值做快照，或要求在直接输出模板之外使用显式格式化操作。普通字面花括号必须仍可用；不要将 JSON 或科学文本误当作模板。
- 不对已构造字符串进行隐式第二次插值。未定义占位符、花括号转义、格式说明和函数局部值都需要明确语义及有帮助的错误。
- 验收：变化值的循环产生不同且正确的行；文本创建后再赋值不能悄悄改变导出内容；测试重复导出、CSV／TSV／文本／JSON 路径、直接 print 模板及解释器／编译器一致性。

### GBL-004 — 无损默认数值文本

```goblin
value = 0.12345678901234567
text = to_text(value)
restored = parse_number(text)
same = value == restored
print("{text}; {same}") # Alpha.19/20: 0.123456789012346; false.
```

alpha.19／20 格式化器在科学计数法中使用 15 位有效数字，但在定点分支中使用 15 **位小数**。两者均不是一般性的 f64 往返还原保证。解释器／生成代码各有格式化实现。JSON 输出和回执序列化有不同路径；不要假设所有封存值已经以同样方式被截断。

Alpha.21 使用共享的最短往返还原格式化器；示例现在打印 `0.12345678901234566; true`。保留带符号零。显式精度仍为经舍入的显示格式。新冻结记录保存格式化政策纪元；执行旧冻结程序须修订，而不是改写回执。参见[契约](NUMERIC_TEXT.md)和 `tests/numeric_text.rs`。

- 默认数值文本和机器可读导出使用最短往返还原十进制格式。可能需要最多 17 位有效数字；并不要求始终打印 17 位。保留明确请求的舍入显示，例如 `{value:.3f}`。
- 将带符号零处理与视觉格式化分开定义。审计 CSV、TSV、`to_text`、stdout、封存序列化和编译输出路径。
- 验收：有限 f64 值的位级往返还原（包含任何有文档说明的带符号零例外）、次正规数、极值及确定性生成案例；继续拒绝非有限值。格式变化须版本化，因为输出哈希将改变；旧保留运行必须仍能验证。

### GBL-005 — 跨平台数学与比较政策

用户报告 macOS arm64 和 Linux x86 的三角函数末位差异。此次工作**未复现**该双平台差异。当前数学使用 Rust／平台浮点操作，而不是固定版本的确定性数学后端。回执已包含运行时版本、操作系统和体系结构（`src/runtime.rs`）；`diff` 已报告环境差异，但这不是数值容差政策。

- 决定受支持运算承诺位级可复现性，还是在明确声明容差内的科学一致性。调查固定版本的纯软件后端，如 `libm`；不要宣称仅一个依赖就能保证所有归约、转换、编译优化和每个目标上的浮点行为。
- 记录数学后端／版本及相关构建／运行时标识。若加入数值比较，则使用明确说明的绝对／相对或 ULP 容差，并检查量纲；绝不能弱化保存证据的字节／哈希验证。
- 验收：macOS arm64／Linux x86、两个执行引擎、定义域边界及极端输入使用共享样例；精确结果和容差结果分开标记。改变数学政策不得悄悄改变旧回执含义或隐藏真实差异。

### GBL-012 — 星表级限制和流式处理

- 定义有界分块／流式读取和处理，和／或显式、可审计的可配置限制。区分文件大小、行／单元格计数、数组元素数、文本大小、内存、输出字节及循环预算。

### GBL-015 — 精确 64 位整数

数值目前使用 f64；`parse_integer` 也返回 f64，并拒绝安全精确范围之外的整数文本。浮点量不是精确 64 位 ID 容器。用户报告这阻碍 Gaia 星表 ID。

- 按需要设计有符号／无符号 64 位表示；规定字面量、解析、算术溢出、比较、数组、转换，以及混合整数／浮点／单位规则。绝不悄悄舍入星表标识符。
- 验收：2^53 附近及有符号／无符号极值、前导零文本政策、经检查的溢出、FITS／CSV／TSV 导入／导出、JSON／回执往返还原及模式兼容、原生一致性，以及有损转换的明确错误。文本 ID 仍是实用临时存储方案。

### GBL-016 — 最低受支持 Rust 版本

`Cargo.toml` 声明 `rust-version = "1.92"`。用户报告 1.91 构建／运行成功；此处尚未验证，且精确构建路径很重要（构建引擎与编译生成的 Rust 有区别）。

- 在候选工具链和受支持目标上测试原始清单／锁定文件、解释器构建、生成的原生程序、测试及 lint。检查 `as_chunks` 等 API 和依赖的最低受支持 Rust 版本（MSRV），而不是凭单个成功可执行文件猜测。
- 完整验收通过后降低声明，或解释具体的 1.92 要求。保持安装文档、CI、包元数据和离线数据编译说明一致。

### GBL-017 — 保留原文件来源的 Gzip 输入

- 新增直接 `.fits.gz` 支持（并决定 gzip 分隔文本输入是否在范围内）。对原始压缩字节进行哈希并保存；按需另记解码流哈希、解压器标识和访问元数据。不能用临时解压文件替代原始输入身份。
- 定义受支持的连接成员／尾随数据政策、CRC 检查、截断输入拒绝、解码大小／压缩比限制、供 FITS 随机访问使用的安全有界临时存储，以及不意外覆盖或访问网络的规则。
- 验收：与未压缩科学数据等价、损坏／大型输入、压缩字节变更、保留的独立验证、原文件执行后检查及原生／解释器一致性。

## 所有实现工作共享的验收门槛

- 宣称修复前添加最小回归测试；分别记录每个平台及每个执行引擎测试了什么。
- 保留量纲、显式失败、冻结／修订谱系／保管链、资源边界、生成产物哈希及旧保留运行验证。
- 将规范化程序、显示值、数学政策、模式和源代码语义的变化作为版本化兼容性决策审查。
- 语言或内置词汇改变时，更新文档、示例、两种编辑器集成、发布说明和包。
- 提交／推送／发布须分别获得授权。记录此清单不授权实现全部功能，也不授权再发布一个发行版。
