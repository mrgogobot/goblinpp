## 复合单位的输入／输出一致性

Malin Hess 于 2026-10-02 报告；已使用本地 alpha.19 发布版可执行文件复现。这是计划修复项，不是已实现功能。

```goblin
acceleration = 1.13e-10 m/s^2
```

目前会因 `G101 UNKNOWN SYMBOL s` 失败。数值字面量解析器只读取一个单位拼写（`m`）；随后 `/s^2` 被当作普通表达式语法，裸 `s` 被求值为名称，而不是单位因子。

受支持的替代写法是：

```goblin
acceleration = 1.13e-10 m / (1 s)^2
```

此写法通过，并显示为 `1.13e-10 m/s^2`。因此，格式化器输出的复合单位记法目前并不能作为等价输入接受。

### 提议范围与验收门槛

- 实现前明确复合单位语法及优先级。接受所报告的加速度形式，使其与替代写法具有相同的值和量纲；覆盖 `kg*m^2/s` 和 `s^-1` 等有代表性的输出形式。
- 不要悄悄重新解释已有表达式、单位幂、常量名、变量除法或科学计数法数字。尤其要区分整个量的乘方与单位指数。
- 测试比例因子的正确应用，并拒绝未知单位、格式错误的单位表达式和不支持的指数。量纲检查必须保持严格。
- 检验解释器／编译器一致性、量纲运算、显示和保留运行的验证。明确规定规范化方式；回归测试现有规范化哈希及冻结源代码约束。
- 若语法处理需要变更，则更新语言参考、示例和两个编辑器插件。

不要为此修复修改已发布的 alpha.19 标签或资产。
