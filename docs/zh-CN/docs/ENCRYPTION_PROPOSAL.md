# 提案：可选的加密导出

**状态：提案，尚未实现。** Goblin++ 目前对证据进行哈希并保存；哈希可以检测变更，却不能隐藏文件内容。`GO_PARANOID` 不是加密开关。在本提案实现并通过测试之前，普通运行目录、导入数据副本、输入回答、参数和日志都必须视为明文。

## 首个实用范围

提供显式 CLI 操作，对单个文件或单个目录快照（例如完整运行包）进行加密和解密。绝不能悄悄加密正常运行输出，也不能改变现有冻结记录或回执的字节。加密导出应在*加密载荷内部*携带清单，记录源包的哈希、格式版本和创建参数。不要把明文哈希、私有路径或秘密作为旁置元数据发布。除非用户另行明确决定如何管理原始证据，否则应原样保留。

采用成熟、经独立审查的加密格式及持续维护的实现，例如 [age](https://github.com/FiloSottile/age)，而不是设计 Goblin++ 自有密码算法。明确选择接收者密钥或口令工作流，包括密钥丢失时如何处理。绝不能将口令或私钥放入 `.gbl` 程序、命令行参数、运行回执、日志或仓库。未来实现必须清楚说明哪些信息仍可见（例如输出文件名、文件大小和任何未加密的元数据）。

## 宣称机密性之前必须通过的验收测试

- 文件和目录的加密／解密往返必须恢复完全相同的字节；恢复的运行包必须通过普通 Goblin++ 验证。
- 错误密钥、错误口令、被修改的密文和被截断的密文都必须安全拒绝；不能接受未经认证的明文。
- 绝不能隐式覆盖已有目标；失败操作不能留下看似完整的输出。
- 目录输入须拒绝符号链接和不安全路径；解包不能写入指定目标之外。须测试空目录、嵌套目录、Unicode 名称和大文件，且不得无界占用内存。
- 密钥和口令绝不能出现在进程参数、程序源代码、回执、日志、崩溃输出或测试样例中。
- 文档必须说明：加密**导出包**不等于加密原始运行目录、临时文件、备份或用户整个磁盘。

此功能可以在范围有限的公开 alpha 之后推出。如果*首次*公开发布承诺加密数据处理，则这些测试和安全审查将成为发布门槛，而非路线图项目。
