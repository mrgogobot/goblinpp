# Rust 引擎架构

引擎有意按照信任边界划分：

- `lexer`、`parser` 和 `ast` 将 UTF-8 源码转换为规范化语义；
- `quantity` 和 `constants` 实现确定性的标量科学计算语义；
- `evaluator` 解释 AST，并记录常量、输出、封存值和数据访问；
- `fits` 以流式方式只读访问多 HDU 元数据及图像／表格数值，无需 C 或 Python 桥接；
- `delimited` 为有大小限制的 UTF-8 CSV/TSV 建立快照，并要求显式数值转换；
- `modules` 静态展开仅含定义的本地导入，并保留原始源码依赖图；
- `output` 验证产物名称，并以确定性方式生成分隔文本、SVG 和无损 PNG 字节；
- `compiler` 生成可供审查的 Rust，调用 `rustc`，或通过离线、锁定依赖的 Cargo 构建共享数据辅助库，不使用 shell；
- `inline_rust` 提取精确的代码字节，并强制执行摘要授权；
- `runtime` 执行保管链运行前检查、程序执行及证据保存；
- `custody`、`ledger` 和 `audit` 冻结历史、建立哈希链，并独立验证历史；
- `main` 提供 `goblin++` 用户界面。

默认采用解释执行。绝不会根据源码内容推断是否编译执行。内联 Rust 不能触发向原生执行的隐式切换。

编译器生成直接操作所生成物理量值的代码，绝不会在运行时调用源码解析器。数据程序链接共享支持库；由于模块依赖关系，该库的源码包含现有解析器，但所生成的入口点不会执行任何 Goblin 源码求值。测试通过检查生成的源码、在 PATH 中没有引擎的情况下独立运行，以及封存生成的源码、支持文件清单和可执行文件，验证这一区别。

## FITS 数据路径

FITS 头以 2,880 字节块读取。数值通过持续打开的文件描述符进行位置读取；数值列统计扫描有大小限制的数据块，而不是将整个文件分配到内存。完整输入哈希通过另一次流式读取计算。`fits-info --quick` 有意跳过完整哈希，并将其输出标记为未计算哈希的初步探查。

运行证据以内容寻址方式存放在 `.goblin/imports/SHA256.fits` 下。首次使用时，系统以流式方式创建候选副本并计算该副本的哈希，只有它与已打开用于求值的字节匹配时才注册。系统支持硬链接时，每次运行会获得指向已存储对象的硬链接，否则使用普通副本作为后备方案。独立运行验证会重新计算所附证据的哈希。

## 生成输出的路径

输出调用在解释器求值期间构造字节，但不能选择操作系统路径。运行时在新运行的 `outputs` 目录下，以排他创建方式将这些字节写入文件。回执绑定文件名、媒体类型、字节数、生成者、元数据和 SHA-256。验证器只接受回执中扁平的 `outputs/NAME` 路径，并重新计算每个产物的哈希。

Alpha.19 的原生调用使用相同的 Rust FITS／表格／输出辅助函数，参数已由生成的代码完成求值。经审计的编译执行会将原生输入访问／哈希描述信息、封存值、输出元数据和字节与参考求值结果进行比较。原生清单和输出副本会接受独立验证。这需要进行两次求值；独立执行的保管链和工作目录边界不同。请参阅 [I/O 指南](DATA_MODULES_NATIVE.md)。

## 库与表格证据

模块静态展开到规范化 AST 中，不执行库的顶层语句。原始源码依赖图条目纳入冻结回执和运行证据。验证时只解析已保存的模块字节。CSV/TSV 访问基于有大小限制的初始快照；表格通过现有的、按校验和寻址的输入证据机制保存，使用 `.csv` 或 `.tsv` 扩展名，并附带明确的操作／列访问描述信息。

FITS 绘图选取确定性的、等间隔行索引，并记录总体行数、请求数、检查数和有效数。PNG 编码采用固定 RGB 尺寸、零号滤波类型和存储式 DEFLATE 块；SVG 的数值布局同样具有确定性。PNG 渲染不依赖系统字体，也不会引入绘图库的运行时依赖。
